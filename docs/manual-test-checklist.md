# 手動テストチェックリスト

Supabase正本版の運用前確認手順です。実在顧客名は使わず、完全に架空の顧客で確認してください。

## 事前準備

1. Supabaseに `supabase/schema.sql` を適用する。
2. Vercelまたはローカル `.env.local` にSupabase URLとpublishable keyを設定する。
3. 職員ログイン用メールアドレスでログインできることを確認する。

## 基本フロー

1. アプリを開く。
2. 職員メールアドレスでログインする。
3. 架空顧客 `TEST001 / サンプル株式会社` を登録する。
4. `2026-05` の面談を作成する。
5. 未完了項目を追加し、`carry_forward=true` にする。
6. `2026-06` の面談を作成する。
7. `2026-05` の未完了・繰越対象項目が `2026-06` の「過去について」に表示されることを確認する。

## 繰越確認

1. `status=open` かつ `carry_forward=true` の項目が繰り越される。
2. `status=in_progress` かつ `carry_forward=true` の項目が繰り越される。
3. `status=on_hold` かつ `carry_forward=true` の項目が繰り越される。
4. `status=done` の項目が繰り越されない。
5. `status=withdrawn` の項目が繰り越されない。
6. `carry_forward=false` の項目が繰り越されない。

## visibility分離

1. `visibility=client` の項目が顧客共有用アジェンダに表示される。
2. `visibility=internal` の項目が顧客共有用アジェンダに表示されない。
3. `visibility=internal` の項目が内部用メモに表示される。
4. `internal_notes` が顧客共有用アジェンダに表示されない。
5. Stock貼付用要約では内部項目が内部メモ欄に区分される。

## 出力確認

1. 顧客共有用アジェンダをコピーできる。
2. 内部用メモをコピーできる。
3. Stock貼付用要約を生成し、コピーできる。
4. 顧客共有用アジェンダを印刷できる。
5. 内部用メモを印刷できる。
6. Stock貼付用要約には印刷ボタンがない。
7. JSONエクスポートができる。
8. JSON内に `sourceOfTruth: "supabase"` が入っている。

## 完了チェック

1. 未チェック項目があると完了扱いにならない。
2. すべてチェックすると完了扱いになる。
3. 期限付き未完了項目がある場合、タスク化チェックが目立つ。

## 守秘確認

1. `.env.local` がGitに含まれていない。
2. secret keyや旧service role keyがコードや環境変数に入っていない。
3. 実在顧客名、実在事務所名、内部資料がサンプルやテストに入っていない。
4. 顧客共有用出力に内部メモが混入していない。
