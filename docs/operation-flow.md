# Stock正本 月次面談アジェンダ管理ツール 運用フロー

このツールはStockの代替ではありません。Stockノート本文と、Stockノートに添付するJSONを正本として扱います。
localStorageは正本ではありません。このツールは顧客データや面談メモをlocalStorageへ保存しません。

## 巡回前

1. Stockで対象顧客の前回月次面談ノートを開く。
2. 前回ノートに添付されたJSONを職員PCへ一時的にダウンロードする。
3. このツールで顧客コードと今回対象月を入力する。
4. 通常開始では、前回JSONを読み込んでから開始する。
5. 顧客コードが一致しないJSONは使わない。
6. 前月以外のJSONを使う場合は、警告内容を確認し、理由を入力して開始する。
7. 前回JSONがない場合だけ、例外開始を使う。

例外開始を使う場面:

- 初回作成
- 新規関与
- 前回面談なし
- データ移行前
- その他、前回JSONが存在しない合理的な理由がある場合

## 面談中

1. 前回からの繰越事項を確認する。
2. 今回新たに発生した事項を追加する。
3. 各項目の担当、期限、状態、次回繰越、公開範囲を更新する。
4. 顧客へ共有する内容は `visibility=client` にする。
5. 顧客へ出さない内部確認事項は `visibility=internal` にする。
6. 内部メモは内部メモ欄に入力する。

状態の考え方:

- 未着手: まだ対応していない。
- 対応中: 着手済みで未完了。
- 完了: 今回で完了。次回へ自動繰越しない。
- 保留: 未完了だが保留。次回繰越対象にできる。
- 取り下げ: 対応不要。次回へ自動繰越しない。

## 面談後

1. 面談結果、決定事項、顧客側宿題、事務所側宿題、内部メモを入力する。
2. 未完了事項の状態を更新する。
3. 次回繰越事項を確認する。
4. Stock貼付用要約を生成する。
5. 今回JSONを出力する。
6. Stockノート本文へStock貼付用要約を貼り付ける。
7. Stockノートへ今回JSONを添付する。
8. 期限付き宿題をStockタスクへ手動で登録する。
9. 面談後チェックリストをすべてチェックし、「Stock保存フロー完了」になったことを確認する。

Stockノートには、必ず次の両方を残します。

- 人間が読めるStock貼付用要約
- 次回読込用の今回JSON

## 顧客共有用と内部用の違い

顧客共有用出力には、`visibility=client` の項目だけを表示します。`visibility=internal` の項目と `internalNotes` は表示しません。

内部用出力には、`visibility=client` と `visibility=internal` の両方を表示します。内部メモも内部用出力に表示します。

Stock貼付用要約は、Stockノート本文へ残す面談記録です。内部メモや内部向け項目は「内部メモ」セクションとして区分します。

## 禁止事項

- 顧客データをGitHubリポジトリへ置かない。
- JSONを職員PCだけに保存したままにしない。
- `visibility=internal` の項目や `internalNotes` を顧客へ共有しない。
- Stock API連携、自動ログイン、Stock画面のスクレイピングを行わない。
- 外部サーバー送信、バックエンド追加、クラウドDB追加を行わない。

## 運用前テスト

ブラウザでの確認手順は `docs/manual-test-checklist.md` にまとめています。運用前レビューでは、正常読込、clientCode不一致、前月以外JSON、例外開始、繰越、visibility分離、Stock貼付用要約、JSON出力、面談後チェックリストを確認します。
