# Supabase正本版 運用フロー

このツールの正本はSupabase Postgresです。Stock添付JSONではありません。

Stockは必要に応じて、面談要約を残す共有先・控えとして使います。Stockへの自動投稿、ログイン自動化、スクレイピングは行いません。

## 巡回前

1. 職員がログインする。
2. 顧客を選択する。未登録の場合は顧客コードと法人名で登録する。
3. 対象月を指定して面談を作成する。
4. 前月の面談がある場合、Supabase上の未完了・繰越対象事項が自動で「過去について」に表示される。
5. 過去・現在・未来の3軸で、面談前に扱うテーマを整理する。

前月JSONのダウンロードや読込は不要です。

## 面談中

1. 「過去について」で、過去実績、前月からの繰越、過去の決定事項や宿題の状況を確認する。
2. 「現在について」で、現在の資金繰り、納付予定、中間納税、相談事項を整理する。
3. 「未来について」で、業績着地予測、短期経営計画、今後の打ち手を整理する。
4. 各項目の担当、期限、状態、次月以降繰越、公開範囲を更新する。
5. 顧客に見せてよい項目は `visibility=client` にする。
6. 顧客に見せない項目は `visibility=internal` にする。

状態の考え方:

- 未着手: まだ対応していない。
- 対応中: 着手済みで未完了。
- 完了: 今回で完了。次月以降へ自動繰越しない。
- 保留: 未完了だが保留。次月以降の繰越対象にできる。
- 取り下げ: 対応不要。次月以降へ自動繰越しない。

## 面談後

1. 決定事項、顧客側宿題、事務所側宿題を入力する。
2. 内部メモを入力する。
3. 顧客共有用アジェンダを確認する。
4. 内部用メモを確認する。
5. Stock貼付用要約を生成する。
6. 必要に応じて顧客共有用アジェンダまたは内部用メモを印刷する。
7. 必要に応じてStockノートへ要約を貼り付ける。
8. 期限付き宿題を必要に応じて別途タスク化する。
9. 完了チェックを付ける。

## 顧客共有用と内部用の違い

顧客共有用:

- `visibility=client` の項目だけ表示する。
- `visibility=internal` の項目を表示しない。
- `internal_notes` を表示しない。

内部用:

- `visibility=client` と `visibility=internal` の両方を表示する。
- `internal_notes` も表示する。

Stock貼付用要約:

- Stock本文へ貼るためのプレーンテキスト。
- 内部項目や内部メモは「内部メモ」欄に区分する。
- 顧客共有用アジェンダとは別物として扱う。

## 禁止事項

- 実在顧客データをGitHubに置かない。
- `.env.local` をコミットしない。
- Supabase secret keyや旧service role keyをブラウザへ出さない。
- `visibility=internal` の項目や内部メモを顧客共有用として渡さない。
- Stock API連携、自動ログイン、画面スクレイピングを行わない。
